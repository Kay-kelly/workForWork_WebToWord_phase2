# WorkForWork WebToWord

This repository contains a Python MVP for a config-driven report pipeline.

## Current MVP Flow

The active entrypoint is:

```text
project/app/pipeline_main.py
```

Current flow:

```text
Excel
-> SharedData
-> generate_image
-> overlay_text
-> build_word
-> PNG + DOCX output
```

`project/app/main.py` and `project/config/mapping.json` are legacy image-flow files. The current MVP should use `pipeline_main.py`.

## How To Run

From the repository root:

```powershell
.\.venv\Scripts\python.exe project\app\pipeline_main.py
.\.venv\Scripts\python.exe project\app\word\inspect_word.py
```

The first command runs the pipeline and generates PNG + DOCX outputs. The second command performs a minimal DOCX inspection.

## Current Outputs

The current sample input produces:

```text
project/output/pipeline_mvp/report_cycle_2.png
project/output/pipeline_mvp/report_cycle_3.png
project/output/pipeline_mvp/report_cycle_5.png
project/output/pipeline_mvp/word/report_cycle_2.docx
project/output/pipeline_mvp/word/report_cycle_3.docx
project/output/pipeline_mvp/word/report_cycle_5.docx
```

`project/output/` is ignored by git and should not be committed.

## Word MVP Scope

The current Word MVP supports:

- Reading a DOCX template through `template_path`.
- Replacing paragraph text placeholders.
- Replacing table-cell text placeholders.
- Replacing `{{cycle_image}}` with the final PNG generated by `overlay_text`.
- Falling back to direct DOCX generation when `template_path` is not configured.
- Inspecting generated DOCX files with `project/app/word/inspect_word.py`.

The current template is:

```text
project/templates/word/mvp_report_template.docx
```

The current Word config is:

```text
project/config/word_templates/mvp_word_report.json
```

## Known Limitations

The current MVP does not support:

- Header/footer placeholders.
- Text-box placeholders.
- Placeholders split across multiple Word runs.
- Complex multi-image layout.
- Visual Word render validation.
- A complete production report template.
